# 몬스터볼 수박게임 (Monster Ball Merge Game) — 설계 문서

작성일: 2026-11-17
상태: 설계 확정 (구현 계획 대기)

## 1. 개요 & 목적

art-poke 사이트에 넣는 **웹 미니게임**. 수박게임(스이카) 머지 퍼즐을 **몬스터볼 테마**로
구현한다. 핵심 목적은 **체류 시간 증가 + 재방문 유도**이며, 전역 **랭킹(리더보드)** 으로
경쟁 요소를 만든다. 기존 `/ranking`과 톤을 맞춘다.

게임 규칙 자체는 수박게임과 동일: 같은 등급의 볼이 닿으면 한 단계 위 볼로 합쳐지고,
통(탱크) 위로 넘치면 게임오버. 최고 등급(마스터볼)을 만드는 것이 목표.

## 2. 핵심 결정 요약

| 항목 | 결정 | 비고 |
|---|---|---|
| 목적 | 체류·재방문 + 전역 랭킹 | `/ranking` 연동 |
| 리더보드 | **역대 최고점 + 월별** | `played_at` 한 컬럼으로 둘 다 집계 |
| 테마 | 몬스터볼 등급 사다리 | 마스터볼 = 최고(수박 자리) |
| 볼 개수 | **총 11등급, 하위 5개만 드롭 가능** | 나머지 6개는 머지로만 등장 |
| 환경 | 데스크탑 우선 + 모바일 반응형 | 입력만 마우스↔터치 분기 |
| 로그인 | **필수** (비로그인 플레이 불가) | `/play` 전체 인증 게이트 |
| 물리엔진 | **matter.js** (헤드리스) | 자체 canvas 렌더링 |
| 점수 검증 | 가벼운 서버 검증 | 상한·빈도·플레이시간·일관성 |
| 에셋 | **코드로 그리는 자체 볼(SVG/canvas)** | 공식 스프라이트 금지(저작권) |
| 컨테이너 UI | **인형뽑기 캐비닛 + 크레인 드롭** | 크레인이 곧 드롭 장치 |

## 3. 기술 선택 근거 (리서치 결과)

- "설치형 라이브러리(`npm install suika-game`)"는 **존재하지 않음**. 공개된 건 전부 standalone 클론.
- 다만 수십 개 클론이 **하나같이 matter.js + 자체 canvas 렌더링** 패턴을 씀 → 사실상 표준.
- 우리 스택과 거의 동일한 레퍼런스 존재: `JhrJianRan/suika-melon` (Next.js + TS + Matter.js +
  Tailwind + 주간 리더보드). **단, 2년 전 코드라 통합 보일러플레이트는 낡음** → 물리·머지
  로직만 "패턴 참고", 통합/백엔드는 우리 스택으로 신규 작성.
- 전략: **matter.js만 의존성 추가**, 게임 로직/렌더링/테마/점수검증은 전부 자체 구현
  (라이선스·테마·유지보수·보안 통제권 확보).
- matter.js vs Rapier.js: 게임 규모(공 50~100개)에선 성능 차이 무의미. matter.js가 순수 JS라
  WASM 비동기 초기화 없이 Next.js와 붙이기 쉽고 레퍼런스가 풍부해 채택. (Rapier는 WASM
  셋업 복잡도만 떠안게 됨)

참고 레퍼런스:

- https://github.com/sgbj/suika-clone (Phaser + Matter.js + TS)

## 5. 아키텍처 — 3층 분리 & 파일 배치

**설계 원칙**: "순수 게임 로직 / React·캔버스 / 백엔드"를 3층으로 분리. 엔진은 React도
matter.js 렌더러도 모르는 순수 TS → 단위 테스트 용이, 점수 신뢰도 유리.

```
domains/game/
  engine/                  ← 순수 TS, React/캔버스 의존 0
    ladder.ts              ← 11등급 정의(등급→반지름·색·스프라이트키·점수·드롭가능여부)
    physics.ts             ← matter.js 월드·벽·중력·바디 생성 (헤드리스, 렌더 안 함)
    merge.ts               ← 같은 등급 충돌 → 다음 등급 생성 + 점수 가산 규칙
    game.ts                ← 게임 루프/상태 오케스트레이션, onMerge 이벤트 emit
    types.ts
  api/
    endpoints.ts           ← API 경로 상수
    types.ts               ← 요청/응답 DTO
  validation.ts            ← 서버측 '가벼운 검증' 로직
  hooks.ts                 ← react-query: 점수 제출 / 리더보드 조회

components/game/           ← 'use client', React + 캔버스 층
  game-canvas.tsx          ← <canvas> 마운트, 엔진 구동, 매 프레임 렌더, 입력(마우스/터치)
  game-cabinet.tsx         ← 인형뽑기 캐비닛 프레임(CSS/SVG 장식)
  game-hud.tsx             ← 점수·다음 공·게임오버 오버레이
  game-leaderboard.tsx     ← 랭킹(역대/월별 탭)
  effects.ts              ← 머지 이펙트 파티클 시스템(렌더러 전용)
  ball-sprites.ts         ← 11등급 볼을 오프스크린 캔버스에 1회 렌더(프로그래매틱)

app/play/                  ← 라우트(이름 임시, 변경 가능), 인증 게이트 뒤
  page.tsx
  loading.tsx
app/api/game/score/route.ts  ← POST 점수제출(검증) / GET 리더보드

lib/db/schema.ts           ← game_scores 테이블 추가(drizzle)
```

**분리 포인트 3가지**
1. matter.js는 **헤드리스로만** — 물리 계산만, 화면은 우리가 canvas에 몬스터볼을 직접 그림 → 비주얼 100% 통제
2. `engine/`은 `'use client'` 밖 순수 TS → vitest로 머지·점수·게임오버 로직을 캔버스 없이 테스트
3. matter.js는 SSR 불가 → `game-canvas.tsx`를 `next/dynamic(..., { ssr: false })`로 클라 전용 로드

## 6. 게임엔진 내부 (`domains/game/engine/`)

- **`ladder.ts`**: 11등급 배열. 각 등급 `{ tier, name, radius, colors, score, droppable }`.
- **`physics.ts`**: matter.js `Engine`+`World`. 좌/우/바닥 정적 벽으로 탱크 형성. 중력.
  "등급→반지름"으로 원형 바디 생성. 렌더러 미부착(헤드리스).
- **`merge.ts`**: `collisionStart`에서 "같은 등급 + 아직 머지 안 된 두 바디" → 둘 제거 →
  중간 지점에 다음 등급 바디 생성 → 점수 가산. 한 틱 중복 머지 방지 플래그. 최고 등급
  (마스터볼)끼리는 터뜨려 보너스(규칙 스펙에서 확정).
- **`game.ts`**: 상태 기계. 보유 상태 `score / nextTier(미리보기) / dropX / isGameOver`.
  메서드 `start() / drop(x) / tick(dt)`. **고정 타임스텝**으로 물리 갱신(프레임 흔들려도
  물리 일정). 렌더러엔 읽기전용 스냅샷만 노출. 머지 발생 시 `onMerge({ x, y, tier, score })`
  이벤트 emit(이펙트는 렌더러가 처리 → 엔진 순수성 유지). 게임오버 = 바디가 상단
  데드라인 위에 N ms 이상 머무름.

## 7. 데이터 흐름 & 백엔드

```
입력(마우스/터치) → game.drop(x) → matter.js 물리 → merge→점수
         ↑ renderer는 매 프레임 snapshot 읽어 canvas에 몬스터볼+크레인 그림
게임오버 → game.ts가 finalScore+stats emit
   → hooks.ts(react-query mutation) → POST /api/game/score
       → validation.ts 통과 → game_scores insert
리더보드 → GET /api/game/score?scope=all|month → 조회(역대최고 / 월별)
```

### 7.1 DB 스키마 (`lib/db/schema.ts` 추가)

```
game_scores
  id          uuid pk
  user_id     uuid  → users.id
  score       bigint
  played_at   timestamp (default now)   ← 월별 집계 기준(WHERE played_at >= 이번달)
  balls_placed smallint                 ← 검증용
  max_tier    smallint                  ← 검증용
  duration_ms bigint                    ← 검증용
  created_at  timestamp
```

- **역대 최고점**: 유저별 `MAX(score)` (전체 기간)
- **월별**: `played_at`이 해당 월인 레코드만 필터 → 매달 자동 리셋 효과(별도 테이블/수동 리셋 불필요)

### 7.2 가벼운 검증 (`validation.ts`, 서버)

- **로그인 필수**(next-auth 세션). 비로그인 제출 거절.
- 제출 빈도 제한(예: 유저당 시간당 N회 — 기존 `report_throttle` 패턴 재사용).
- `score ≤ ballsPlaced 기준 이론상 최대치`, `durationMs ∈ [3초, 2시간]`,
  `score↔max_tier 일관성` → 벗어나면 400 거절.
- 한계 인지: 가벼운 검증은 "그럴듯한 위조 payload"를 막지 못함. 상금·보상 없는 순수
  경쟁이므로 수용 가능(의도된 트레이드오프).

## 8. 인증 — 로그인 필수

- `/play` 라우트 전체를 **인증 게이트** 뒤로. 비로그인은 로그인 페이지로 리다이렉트
  (기존 next-auth 미들웨어/패턴 재사용).
- 플레이어는 항상 로그인 상태 → 게임오버 시 점수 등록 분기 단순.

## 9. 에셋 — 코드로 그리는 자체 볼

**저작권 함정 회피**: 이 프로젝트는 이미 공식 카드 이미지가 저작권·S3 문제로 깨진 이력이
있음. **공식 포켓몬 볼 스프라이트를 쓰면 같은 지뢰를 재방문**(공개 랭킹 사이트라 더 위험).

**자체 프로그래매틱 볼**:
- 포켓볼은 도형이 단순(원을 상/하 2색 분할 + 가운데 띠 + 중앙 버튼 흰 링). 등급마다 색
  팔레트만 다르게 11종.
- 각 등급 볼을 **오프스크린 캔버스에 1회 미리 렌더**(`ball-sprites.ts`) → 매 프레임
  `drawImage`만 (100개도 가뿐, 머지 애니메이션에도 선명).
- 저작권 0, 번들 극소, 임의 크기 선명, #EE1515 디자인시스템과 일관.
- 공식 "트레이드 드레스(로고 등)"는 피하고 일반적 2색+띠 볼 디자인으로.

## 10. 컨테이너 UI — 인형뽑기 캐비닛 + 크레인

인형뽑기 컨셉이 수박게임 조작과 일치:
- **크레인(집게)이 곧 드롭 장치**. 마우스/터치 따라 좌우 이동, 클릭/탭 시 집게가 열리며
  볼 낙하. "보이지 않는 드롭 위치" 대신 집게가 그 역할 → 테마·조작 일체화.
- **물리는 그대로** — 탱크 내부 좌/우/바닥 3개 정적 벽만. 집게·캐비닛은 **렌더러 층
  장식**이라 물리 복잡도 0.
- 집게는 엔진 스냅샷(`dropX`, `nextTier`)만 읽어서 그림 → 엔진 순수성 유지.

**구현 분담**
- 바깥 캐비닛 프레임 → `game-cabinet.tsx` CSS/SVG(선명·간단)
- 유리 탱크 내부(볼·물리) → `<canvas>`
- 집게 크레인 → canvas에 그림(드롭 위치와 픽셀 정렬)

## 11. 머지 이펙트 "손맛"(juice)

**이펙트는 엔진이 아니라 렌더러 층에서**. 엔진은 `onMerge` 이벤트만 쏘고, `effects.ts`가
받아 이펙트 생성(엔진 테스트 가능성 유지). 라이브러리 없이 canvas로, 같은 rAF 루프에서 처리:
- 파티클 팝(머지 지점에서 그 볼 색 입자 버스트)
- 스케일 펀치(새 볼 살짝 크게 튀어나왔다 원래 크기 — 오버슈트/스쿼시)
- 확산 링(투명해지며 퍼지는 원 테두리)
- +점수 플로팅 텍스트(위로 떠오르며 소멸)
- 마스터볼 머지: 더 큰 버스트 + 짧은 글로우(최고 등급 특별 연출)
- (선택) 짧은 "뽕" 효과음 + 음소거 토글

구현: `effects.ts`에 가벼운 파티클 시스템(배열로 위치·속도·수명 관리). 외부 의존성 0.

## 12. 예외처리 & 엣지케이스

- **SSR**: matter.js 브라우저 전용 → `game-canvas.tsx` `dynamic(..., { ssr: false })`.
- **리사이즈**: 물리 월드는 가상 고정단위, 렌더만 비율 스케일 → 창 크기 변경에도 안 깨짐.
- **탭 백그라운드**: `visibilitychange`로 루프 일시정지(큰 dt 물리 폭발 방지) + 고정
  타임스텝으로 dt 상한.
- **제출 실패(네트워크)**: react-query 재시도 1회(5xx만), `sonner` 토스트 알림, 로컬 최고점
  localStorage 보존.
- **오버플로 오탐**: 드롭 중 순간적 데드라인 침범은 디바운스로 게임오버 오판 방지.
- **입력 분기**: 마우스(move/click) ↔ 터치(touchmove/touchend) 핸들러 분리, 동일 `game.drop` 호출.

## 13. 테스트 전략

- **vitest(스택 보유)** — 순수 로직, 캔버스 없이:
  - `ladder.ts`: 등급 단조증가(반지름·점수), 11등급·드롭5 유효
  - `merge.ts`: 같은등급→다음등급+정확한 점수, 최고등급 처리, 중복머지 없음
  - `game.ts`: 모의 바디 위치로 게임오버 판정, 점수 누적
  - `validation.ts`: 상한·빈도·일관성 위반 거절
- **Playwright(`test:e2e` 보유)**: `/play` 로드(로그인 상태)→캔버스 렌더→공 하나 드롭 스모크,
  비로그인 접근 시 로그인 리다이렉트.
- 물리 시뮬의 완전 결정론엔 **의존하지 않음**(로직을 물리에서 분리).

## 14. 스펙에서 확정할 숫자 (플레이스홀더)

구현 계획 단계에서 확정. 기술 설계엔 영향 없음:
- 11등급 각각의 반지름·색 팔레트·점수값
- 탱크 크기(가상 단위), 데드라인 높이
- 드롭 쿨다운(연속 드롭 간격), 다음 볼 랜덤 풀(하위 5)
- 게임오버 데드라인 체류 임계 N ms, 오버플로 디바운스 시간
- 제출 빈도 제한 수치, duration 허용 범위
- 마스터볼끼리 머지 시 보너스 규칙(터뜨림 여부·점수)

## 15. 비목표 (YAGNI)

- 멀티플레이/실시간 대전 (tsuika 같은) — 안 함
- 서버 재시뮬레이션 기반 철저한 안티치트 — 안 함(가벼운 검증만)
- 카드 수집/재화 연동 보상 — 이번 범위 밖(목적이 랭킹이므로)
- AI/공식 스프라이트 에셋 — 안 함(자체 SVG)
