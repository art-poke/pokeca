# EPIC: 커뮤니티·랭킹·도안 상세 고도화

Generated by /spec on 2026-10-31. Status: DRAFT (유저 확정, /autoplan 검증 예정).
Repo: art-poke/pokeca. 설계 선행 문서: `extended-art-archive-mvp.md`.

## Context (Why)

수집가가 단순 검색·다운로드를 넘어 **참여(추천·댓글·커뮤니티)** 하고, 작가는 **랭킹**으로 동기부여받는 플랫폼으로 확장한다. 현재는 익명 방문자만 존재해 참여 기능이 불가능하므로 **일반 회원(member)** 도입이 모든 기능의 기반이다.

**핵심 변경(주의):** 다운로드가 **익명 → 회원 전용**으로 바뀐다. 모든 다운로드에 `user_id`를 기록한다.

## 누구

- 수집가(일반 회원): 추천·다운로드·댓글·커뮤니티·도안 요청
- 작가: 랭킹 대상, 도안 제목 입력
- 어드민: 공지 작성, 글·댓글 모더레이션

## 의존 그래프

```
#1 회원 계정(member) ─┬─> #2 추천·점수·랭킹(engagements)
                      ├─> #3 도안 상세페이지 + 댓글 + 추천
                      ├─> #4 도안 요청 + 요청목록(요청방)
                      └─> #5 커뮤니티(게시판)   (#5 댓글은 #3 comments 재사용)
```
**순서 근거:** #1은 나머지 전부의 정체성 기반. engagements 테이블(#2)은 #3의 추천/다운로드가 공유. comments(#3)는 #5가 재사용. 따라서 #1 → #2 → #3 → (#4, #5).

## 신규/변경 스키마

모든 테이블 RLS on·정책 없음, 서버 `lib/supabase/server.ts`의 `db()`만 접근. 함수 실행권한 `service_role`만. `tests/integration/access-boundary.test.ts`가 RLS/권한 누락 검사.

```sql
-- #1
create table members (
  user_id uuid primary key references auth.users(id),
  nickname text not null,
  created_at timestamptz not null default now()
);

-- #2  (user,도안)당 1행 = 1점, 중복불가(다운로드 or 추천)
create table engagements (
  user_id uuid not null references auth.users(id),
  artwork_id uuid not null references artworks(id),
  kind text not null check (kind in ('download','recommend')),
  created_at timestamptz not null default now(),
  primary key (user_id, artwork_id)
);
create index engagements_artwork on engagements(artwork_id, kind);
create index engagements_created on engagements(created_at);

-- #3/#5  다형 댓글 + 1단계 대댓글
create table comments (
  id uuid primary key default gen_random_uuid(),
  target_type text not null check (target_type in ('artwork','post')),
  target_id uuid not null,
  user_id uuid not null references auth.users(id),
  parent_id uuid references comments(id),   -- 1단계 대댓글만(부모는 parent_id null)
  body text not null,
  created_at timestamptz not null default now(),
  deleted_at timestamptz
);
create index comments_target on comments(target_type, target_id, created_at);

-- #5
create table posts (
  id uuid primary key default gen_random_uuid(),
  board text not null check (board in ('notice','suggestion','free')),
  user_id uuid not null references auth.users(id),
  title text not null,
  body text not null,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  deleted_at timestamptz
);
create index posts_board on posts(board, created_at desc);

-- 변경
alter table artworks add column title text;         -- #3 작가 입력, 기본 "{작가}님의 도안"
alter table requests add column user_id uuid references auth.users(id);  -- #4 회원 요청
```

## #1 — 일반 회원 계정 (Foundation)

- 기존 소셜 로그인 재활용. `currentSocialUser()`는 이미 비작가 소셜 유저도 반환 → `members` 테이블 + `currentMember()`(첫 참여 시 소셜 이름으로 nickname 자동 생성, upsert).
- 표시 이름 = 작가면 `artists.display_name`, 아니면 `members.nickname`.
- 전역 헤더 유저메뉴는 작가/member 모두 지원(이미 auth-menu 존재, member 분기 추가).

**수용기준**
1. 비로그인 유저가 추천·다운로드·댓글·글쓰기 시도 → 로그인 유도(/artist/login 재사용 또는 공용 /login).
2. 로그인 회원은 닉네임으로 활동, 닉네임 없으면 소셜 이름 자동 세팅.
3. `members` 테이블 RLS on, access-boundary 테스트 통과.

## #2 — 추천·다운로드 점수 + 랭킹

- `engagements` PK(user_id, artwork_id)로 **중복불가** 강제.
- **다운로드**(회원만): 서버가 파일 서빙 + engagement(`download`) 기록(없을 때만). 비회원 다운로드 차단.
- **추천**(회원만): 토글. 행 없으면 `recommend` 삽입, 이미 `recommend`면 취소, 이미 `download`면 차단("이미 다운로드로 반영됨").
- **작가 점수** = 자기 active 도안들의 engagements(download+recommend) 고유 수.
- **도안 랭킹** = 추천(`recommend`) 수 내림차순.
- 기간 탭: **금주(ISO week)·이번달·역대** — `engagements.created_at` 필터. 초기 온디맨드 집계(카운트 작음), 추후 집계 테이블/뷰로 최적화.
- `/ranking` 페이지: `금주/이번달/역대 × 작가/도안` 탭. 홈 "주간 작가 랭킹" mock → 실제 데이터 요약본으로 교체. 사이드바 "랭킹" 메뉴 추가.

**수용기준**
1. 회원 추천 1회 → 작가 점수 +1, 같은 유저 같은 도안 재추천 불가(PK 충돌).
2. 다운로드한 도안엔 추천 불가(차단 메시지).
3. 도안 랭킹 추천수 내림차순, 작가 랭킹 engagement수 내림차순.
4. 기간 탭 전환 시 해당 윈도우 집계만.

## #3 — 도안 상세 페이지 + 댓글 + 추천

- **`/artworks/[id]`** 신설(모달 ArtworkViewer 제거). 상세: 큰 이미지·**제목**·규격·**작가명**·출처·**다운로드(회원)**·**추천(회원)**·**댓글(1단계 대댓글)**.
- 그리드 아이템(`ArtworkItem`): 다운로드 버튼/더보기-다운로드 제거, 클릭 → 상세 이동. 표시 = 도안 이미지·제목·규격·작가명.
- `artworks.title` 추가(작가 업로드 폼 입력, 기본 "{작가}님의 도안"). 기존 데모/도안 백필.
- 댓글: `comments`(target_type='artwork'). 회원 작성, 본인/어드민 삭제(soft delete). 대댓글 1단계.

**수용기준**
1. 아이템 클릭 → 상세 페이지 전환(모달 아님).
2. 상세에서 다운로드·추천·댓글·대댓글 동작.
3. 댓글 작성자 = 로그인 회원, 본인/어드민만 삭제.
4. artworks.title 없는 기존 행 백필 완료.

## #4 — 도안 요청 + 요청목록(요청방)

- `requests.user_id` 추가(회원 요청). 카드 페이지에 **"도안 요청" 버튼**(특히 도안 없을 때). 기존 빈-규격 "찾기 요청"과 통합/정리.
- 사이드바 **"도안 요청해요"** → `/requests`: **카드별 요청수 랭킹**(많이 요청된 카드 상단 = 요청방). 클릭 → 카드 페이지.

**수용기준**
1. 회원이 카드 요청 → 요청수 +1(유저당 1회, unique).
2. `/requests` 목록 요청수 내림차순.
3. 요청 많은 카드가 상단.

## #5 — 커뮤니티 (게시판)

- `posts` + 사이드바 **"커뮤니티"** → `/community`: 탭 **공지사항/건의사항/자유게시판**. 목록·상세·작성.
- 권한: **공지=어드민만 작성**(누구나 읽기·댓글), 건의·자유=회원 작성. 모든 글 댓글 가능(#3 comments 재사용, 대댓글 포함). 본인/어드민 글·댓글 삭제.

**수용기준**
1. 회원이 건의/자유 글 작성·댓글.
2. 공지는 어드민만 작성, 누구나 댓글.
3. 본인/어드민만 글·댓글 삭제.

## 사이드바 최종

홈 · 카드 검색 · **랭킹** · **도안 요청해요** · **커뮤니티** · 작가 스튜디오 · 권리자 내림 요청

## Out of scope

인쇄 엔진 · 알림(이메일/푸시) · 커뮤니티 이미지첨부/리치에디터(1차 텍스트만) · 신고 자동숨김 확장.

## 알아둘 함정 (eng)

- Next.js 16 cacheComponents: 세션/방문자 의존 조회는 `await connection()` 선행(기존 `authClient` 패턴).
- 다운로드 회원화 → `/api/download/[id]` 익명 허용 제거(회원 세션 요구). 인쇄 안내 노출 로직 유지.
- engagements/requests는 `visitor_id`(익명) 대신 `user_id`(회원)로. 기존 익명 `events.download`는 측정용으로 유지하되 점수엔 미반영.
- 모든 신규 테이블 access-boundary 테스트 추가.
