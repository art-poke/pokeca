# 아트포케 마케팅 대시보드와 회원 관리 설계안

2026-11-23 · 프론트엔드, 서버, 운영 지표 공동 명세

## 1. 운영자가 처음 보는 화면

`/admin`은 “오늘 누가 얼마나 왔고, 어디서 가입했으며, 다시 돌아오는가?”에 답한다. 작품 목록과 점검 필터의 진입점은 `/admin/artworks`로 둔다. 기본 메뉴는 **대시보드 · 인사이트 · 회원 · 작품 · 신고**다. 작품 등록은 작품 화면의 주요 버튼으로, 로그아웃은 계정 메뉴로 이동한다.

| 화면 순서 | 표시할 내용 | 클릭 시 |
| --- | --- | --- |
| 기간 | 오늘, 어제, 최근 7일·30일, 이번 달, 날짜 직접 선택. 일별·월별 전환, KST 기준 시각과 마지막 갱신 표시 | 선택 기간과 집계 단위를 URL에 보존 |
| 핵심 지표 | 순방문자, 활동 방문자, 신규 가입, 전체 회원. 각 카드에 비교 기간의 실제 값과 증감 인원 표시 | 해당 지표의 시계열과 정의 |
| 추이 | 방문·활동 추이, 회원 증가 추이를 각각 표시. 회원 차트에는 신규·탈퇴와 기간 말 회원 수를 함께 표시 | 특정 날짜나 달의 내역 |
| 가입 전환 | 비로그인 진입 → 로그인 시작 → 인증 성공 → 신규 가입. 페이지·버튼별 방문 수, 시도 수, 신규 가입 수, 전환율 | 인사이트의 가입 탭 |
| 재방문과 서비스 이용 | 가입 코호트 D1·D7·D30, 검색·도안·랭킹·게임·요청·카드 이야기·커뮤니티별 방문 및 주요 행동 | 해당 영역의 상세 지표 |

오늘 14:30의 방문자 카드는 예를 들어 **120명 · 어제 같은 시각 100명(+20명, +20%) · 지난주 같은 요일 같은 시각 150명(−30명, −20%)**으로 읽힌다. 예시는 가상 수치다. 지난 날짜는 하루 전체끼리 비교한다. 이번 달은 전월 같은 경과 시각까지, 날짜가 짧은 달은 양쪽에 존재하는 마지막 날까지 비교하고 경계를 표시한다. 사용자 지정 기간은 직전 같은 길이 구간과 비교한다. 기준값이 0이면 인원 차이와 ‘비율 계산 불가’를 표시한다.

## 2. 숫자를 세는 기준

| 지표 | 단위와 계산 |
| --- | --- |
| 순방문자 | 기간 중 사용자 화면이 실제 표시된 `page_view`의 고유 방문 쿠키 `vid`. 로그인 전후 같은 브라우저를 한 번 센다. 브라우저·기기 변경이나 쿠키 삭제는 별도 방문자로 잡힐 수 있다. |
| 활동 방문자 | 같은 기간에 아래 사전의 ‘활동’ 이벤트를 1회 이상 발생시킨 고유 `vid`. 단순 메뉴 이동, 로그인 시작, 페이지 노출은 활동에서 제외한다. 페이지 수집 누락 때문에 방문자와 활동자의 모수가 다른 경우 집계 상태에 표시한다. |
| 활동 회원 | 활동 이벤트 당시 로그인한 고유 회원 ID. DAU는 하루, WAU는 끝 날짜 포함 최근 7일, MAU는 최근 30일이다. 월별 차트의 ‘월간 활동 회원’은 해당 달 전체의 고유 회원 수다. 일별 순방문·활동 수를 합산해 월간 고유 수를 만들지 않는다. |
| 전체 회원 | 시점 기준으로 소셜 가입을 완료하고 아직 탈퇴하지 않은 고유 계정 수. 소셜 회원이 관리자 역할도 가지면 한 회원으로 센다. 운영용 비밀번호 전용 계정은 제외한다. |
| 회원 증가 | 신규는 해당 기간 첫 소셜 가입 계정 수, 탈퇴는 해당 기간의 회원 탈퇴 수, 순증은 신규 − 탈퇴. 현재 회원 수와 누적 가입 수에 서로 다른 라벨을 쓴다. |
| 회원 리텐션 | KST 가입 날짜별 코호트에서 가입 D+n 날짜에 활동한 고유 회원 / 해당 코호트 가입 회원. D1·D7·D30을 각각 계산한다. 아직 해당 날짜가 끝나지 않은 셀은 ‘관찰 중’, 집계 대상 0명은 ‘—’다. 여러 코호트의 비율은 분자·분모를 합쳐 계산한다. |
| 방문자 재방문율 | 기간 순방문자 중 기간 시작 전에도 방문이 관측된 `vid`의 비율. ‘첫 관측’ 기준일을 표시한다. 회원 리텐션과 구분한다. |

관리자 콘솔, QA 계정·테스트 방문, 확인 가능한 봇·프리페치 요청을 마케팅 집계에서 제외한다. 운영자가 일반 서비스를 사용하는 트래픽은 내부 트래픽으로 표시해 기본 제외하되 회원 원장의 전체 회원 수는 별도로 계산한다.

## 3. 이벤트 택소노미

모든 사용자 화면은 공통 이름 `page_view`, 모든 측정 대상 버튼과 링크는 `cta_clicked`를 쓴다. 어떤 화면인지 `page_id`, 어떤 의도인지 `action_id`, 어디에 있었는지 `placement`로 구분한다. 글자·색상·모바일 레이아웃이 바뀌어도 식별자는 유지한다. 기능 완료는 도메인 이벤트로 따로 기록한다. 예를 들어 도안 받기 버튼은 `cta_clicked / download_artwork`, 서버가 파일 응답이나 서명 URL을 준비한 시점은 `artwork_download_issued`다.

**이름 규칙.** 영문 소문자 snake_case. 도메인 이벤트는 대상과 발생 사실을 표현한다. 버튼 식별자는 동사+목적어로 짓는다. 동적 카드 번호·닉네임·버튼 문구는 이름에 넣지 않는다. 이벤트 사전에 정의·발생 조건·발행 주체·허용 속성·활동 여부·버전을 등록한다. 의미가 달라지면 버전을 올리고 집계 적용일을 남긴다. 등록되지 않은 이름은 개발 단계에서 검출하고 운영에서는 별도 오류 건수로 집계한다.

| 화면 | page_id 예시 | action_id 예시 |
| --- | --- | --- |
| 홈·검색·카드 | home, search_results, card_detail | submit_search, select_card, favorite_card, request_artwork |
| 도안·작가 | artwork_list, artwork_detail, artist_profile, artwork_upload | download_artwork, open_source, recommend_artwork, publish_artwork |
| 랭킹·요청 | ranking, request_list | change_ranking_period, select_ranked_item, request_artwork |
| 게임 | game_hub, game_play | select_game, start_game, replay_game |
| 콘텐츠·커뮤니티 | story_list, story_detail, community_board, post_detail, post_editor, review_list | read_story, like_story, write_post, submit_comment |
| 로그인·내 계정 | social_login, my_account, artist_studio | start_login, choose_provider, edit_profile |

라우트 사전은 화면을 실제로 보여준 경로 기준으로 매핑한다. 예를 들어 `/cards/[set]/[number]`는 `card_detail`, `/play`와 `/card-fragments/[game]`은 `game_play`와 별도 `game_id`를 쓴다. `/artist/login`은 가입 퍼널에 포함한다. 탭·랭킹 기간 변경은 속성과 행동으로 기록한다. 기본 페이지 조회는 최초 표시, 실제 SPA 이동, 뒤로가기에서 발생한다. URL 미리 불러오기, 리렌더, 탭 전환만으로 조회를 추가하지 않는다. 다른 ID의 카드·게시물로 이동하면 같은 화면 유형에서도 새 조회다.

| 이벤트 | 발생 시점과 기록 주체 | 속성 예시 | 활동 |
| --- | --- | --- | --- |
| page_view | 브라우저에 화면 표시 | page_id, page_view_id, content_id |  |
| cta_impression / cta_clicked | 가입 유도 요소가 화면에 50% 이상 1초 노출 / 등록된 버튼·링크 활성화. 키보드 포함. 노출은 동일 페이지뷰·버튼·위치당 1회 | action_id, placement, page_view_id |  |
| search_results_returned | 서버에서 첫 검색 결과 확정. 결과 한 건의 자동 상세 이동도 포함 | search_id, 정제 검색어, 첫 페이지 건수, has_more | 활동 |
| artwork_source_opened / artwork_download_issued | 원본 링크 활성화 / 서버가 다운로드 응답 준비 | artwork_id, card_id | 활동 |
| favorite_added / artwork_recommended / artwork_published | 서버가 즐겨찾기 추가·추천·도안 발행 확정 | 대상 ID, 작업 ID | 활동 |
| request_created / request_resolved | 서버에서 요청 신규 생성 / 해결 처리 | request_id, request_kind, card_id(있을 때) | 활동 |
| ranking_item_selected | 랭킹에서 항목을 열 때 브라우저가 기록 | ranking_kind, period, position, target_id | 활동 |
| game_started / game_finished / game_score_saved | 첫 플레이 입력 / 게임 종료 / 서버가 점수 저장 확정 | game_id, round_id, mode | 활동 |
| story_read / story_liked | 본문을 전경에서 누적 10초 읽음 / 서버가 좋아요 추가 확정 | story_id | 활동 |
| post_published / comment_created / review_created | 서버가 글·댓글·후기 저장 확정 | 콘텐츠 유형과 ID | 활동 |
| login_prompt_viewed / oauth_started | 로그인 안내 표시 / 서버에서 공급자 이동 시작 | origin_page_id, origin_action_id, placement, attempt_id, provider(선택 후) |  |
| login_succeeded / signup_completed | 서버가 소셜 인증 성공 확인 / 그중 신규 계정 첫 성공 | provider, attempt_id, 내부 회원 키 |  |
| oauth_failed | 서버가 확인한 인증 오류·취소. 무응답은 기한 경과로 따로 계산 | attempt_id, 허용된 사유 코드 |  |

영역별 인사이트는 방문 수와 고유 방문자에 각각 결과 지표를 붙인다. 랭킹은 항목 선택률, 게임은 시작·완주·점수 저장률, 요청은 신규·해결·미해결 수와 해결 소요 시간, 검색은 인기 검색어·0건 비율·카드 상세 도달률, 도안은 다운로드 발급·원본 이동, 이야기는 읽기율, 커뮤니티는 작성·반응을 본다. `round_id`·`search_id`·`request_id`로 같은 활동을 연결하고, 각 비율에는 분자와 분모 건수도 표시한다.

## 4. 비로그인 방문에서 가입까지

예를 들어 카드 상세에서 도안 받기를 누르고 카카오로 가입하면 운영자는 **카드 상세 / 도안 받기 / 도안 목록 / 카카오 / 신규 가입 1명**을 본다. 헤더 로그인, 즐겨찾기, 게임 시작, 요청, 댓글, 작가 업로드도 같은 방식으로 비교한다.

1. 방문 세션 첫 페이지에 유입 도메인과 허용된 UTM source·medium·campaign을 붙인다. 무활동 30분 뒤 새 세션을 시작한다. 사이트 내부 이동이나 OAuth 공급자 복귀가 세션 최초 유입값을 덮어쓰지 않게 한다.
2. 비로그인 이용자의 버튼 노출·클릭, 로그인 안내, 로그인 화면을 연결한다. 공통 로그인 진입 함수가 출발 화면·버튼·위치·페이지뷰를 전달한다. 보호 경로 직접 진입은 원래 목적 화면과 `direct_route`를 기록한다. 클릭을 관측하지 못한 경우에는 클릭을 생성하지 않는다.
3. `app/artist/actions.ts`의 socialLogin에서 공급자를 검증하고 수명이 짧은 서버 측 로그인 시도 레코드를 만든다. 브라우저에는 불투명한 시도 키만 둔다. 출발 세션과 시도는 OAuth가 30분 방문 경계를 넘겨도 연결할 수 있다.
4. Auth.js의 검증된 성공 콜백에서 카카오·구글만 대상으로 회원 ID와 isNewUser를 읽는다. 모든 성공은 login_succeeded, 첫 소셜 가입 성공은 signup_completed도 한 번 기록한다. 기존 회원 재로그인은 신규 분자에서 제외한다. 로그인 작업과 계측 오류를 분리하고, 가입 원장과의 차이를 점검한다.
5. 공급자 왕복은 시도별 서명된 내부 복귀 경로와 서버 기록으로 연결한다. Auth.js의 state·PKCE 검증을 유지한다. 다른 탭의 로그인, 재시도, 만료된 키 등으로 시도가 모호하면 출처 미상으로 분류하고 성공 총수는 보존한다. 회원 탈퇴 후 새 계정으로 재가입하면 새 회원 ID로 센다.

| 운영 질문 | 분모 | 분자 |
| --- | --- | --- |
| 어느 페이지에서 비회원이 가입하는가 | 해당 페이지를 본 고유 비로그인 세션 | 그 페이지에서 시작한 시도로 신규 가입까지 마친 동일 세션 |
| 어느 버튼이 가입을 유도하는가 | 해당 버튼·위치가 노출된 고유 비로그인 세션 | 노출을 관측한 뒤 그 버튼에서 시작해 가입한 동일 세션 |
| 버튼을 눌러도 어디서 이탈하는가 | 해당 버튼을 클릭한 고유 비로그인 세션 | 같은 출처로 OAuth 시작 / 성공 / 신규 가입에 도달한 동일 세션을 단계별 표시 |
| 공급자별 인증 성공률은 어떤가 | 카카오·구글 각각의 고유 OAuth 시작 시도 | 동일 attempt_id의 성공. 신규·재로그인 비중도 함께 표시 |

가입 기여는 성공한 시도의 출발점 한 곳에 귀속한다. 전체 전환율은 필터 안에서 세션을 다시 중복 제거한다. 공급자별 성공률은 시도 단위다. 첫 랜딩 채널과 가입 직전 버튼을 서로 다른 열로 제공한다. 퍼널은 같은 세션·시도에서 앞 단계를 거친 사실과 순서를 검사한다. 카드 검색 결과 한 건의 자동 이동은 카드 상세 도달에 포함하고 결과 버튼 클릭 단계는 건너뛴 것으로 표시한다.

## 5. 프론트엔드와 서버

| 구성 | 설계 |
| --- | --- |
| 웹 수집기 | 루트 레이아웃에서 실제 표시된 사용자 페이지를 관측한다. 공통 버튼·링크와 로그인 안내 컴포넌트에 타입 검사된 계측 속성을 부여한다. 페이지별 첫 노출·뒤로가기·동일 화면 내 콘텐츠 이동을 테스트한다. 실패해도 사용자 동작을 계속한다. |
| 수집 API | 기존 POST /api/events를 확장한다. 브라우저가 보낼 수 있는 종류와 속성을 제한한다. 서버가 HttpOnly vid와 인증 세션에서 신원을 읽고 서버 수신 시각을 붙인다. 회원가입·점수 저장·요청 생성 같은 완료 이벤트는 해당 서버 로직에서만 발행한다. |
| 저장 | 기존 events에 스키마 버전, event_id, session_id, page_view_id, 선택적 회원 키, 발생·수신 시각을 추가한다. event_id 유일 제약으로 재전송을 제거하고 서버 완료 이벤트에는 작업별 중복 방지 키를 둔다. signup_completed는 계정당 1회다. |
| 정합성 | KPI의 원장은 회원·요청·도안 등 실제 저장 레코드다. 중요한 완료 이벤트는 업무 트랜잭션에서 함께 기록하거나 같은 트랜잭션의 outbox로 전달한다. OAuth 외부 왕복은 콜백 재처리와 원장 대조로 보완한다. 브라우저 이벤트는 누락 가능성을 품질 지표로 표시한다. |
| 집계와 화면 | 기존 Next 서버와 RDS를 재사용한다. /admin과 /admin/insights는 서버에서 requireAdmin을 통과한 후 기간·세그먼트별 집계를 조회한다. 방문자·회원·세션 단위로 각각 중복 제거한다. 대시보드는 일부 쿼리가 실패하면 해당 패널에 마지막 갱신 시각과 오류를 표시한다. |
| 운영 비용 | 처음에는 기간 제한과 시간·방문자·회원·시도 인덱스를 적용해 직접 집계한다. 30일 조회 실행 계획과 응답 시간을 측정한 뒤 병목 집계만 일별 요약한다. 월간 고유 수와 코호트를 복원할 때는 중복 제거 가능한 방문자·회원별 활동일을 쓴다. |
| 데이터 최소화 | 경로는 템플릿, referrer는 도메인, 버튼은 등록된 키를 쓴다. 이메일·전화번호 패턴을 검색어에서 제거하고 길이를 제한한다. OAuth 토큰·전체 URL·입력폼 내용은 분석 속성에서 제외한다. 현재 보유 기준은 개인정보처리방침의 집계·개선 목적에 따른다. 원시 이벤트 90일과 비식별 집계 13개월은 후속 자동 삭제·집계 작업에 대한 제안이다. |

## 6. 회원 관리

`/admin/users`에서 핸들·닉네임·UUID 검색, 가입일·인증 공급자·상태·역할 필터, 페이지네이션을 제공한다. 목록에는 가입일, 마지막으로 관측된 활동, 계정 상태, 역할을 표시한다. 상세에서는 최초 가입 유입과 기능별 활동 요약, 운영 조치 이력을 확인한다. 기존 회원의 출처와 마지막 활동을 복원할 근거가 없으면 ‘미수집’으로 표시한다.

첫 운영 기능은 계정 이용 정지·해제와 관리자 부여·회수다. 정지 범위는 로그인 및 회원 전용 작업으로 정한다. 서버의 세션·회원·관리자 가드에서 현재 상태를 확인해 이미 발급된 JWT에도 조치가 적용되게 한다. 관리자 부여는 기존 소셜 사용자 ID를 기준으로 수행한다. 권한 변경은 별도의 권한 관리 권한이 있는 운영자만 실행하며, 이 권한의 초기 소유자는 출시 시 운영자가 지정한다. 일반 회원 목록 열람 권한과 구분한다.

조치마다 대상·사유·실행자·변경 전후 상태·시각을 하나의 트랜잭션에 기록한다. 자기 권한 회수와 마지막 권한 관리자의 정지·회수를 막고 동시 변경에도 같은 규칙을 적용한다. 상세 화면은 이메일이 없는 소셜 계정도 조회·조치할 수 있어야 한다. 권한 변경 시 인증용 이메일 또는 비밀번호를 생성하지 않는다. 기존 admins.email 필드의 감사 표시 용도는 별도의 실행자 ID로 이관하고 기존 행과 호환되게 한다. 회원 탈퇴는 현재의 익명화·OAuth 연결 해제 흐름을 따른다. 계측 회원 키 연결도 제거하고, 권한 검사에서 탈퇴 상태를 확인한다.

## 7. 적용 순서와 출시 판정

1. **기준선 확보.** 운영 events의 종류별 최초·마지막 시각, 일별 저장량, 실제 CHECK 제약, 마이그레이션 이력을 읽기 전용으로 확인한다. 662baab의 추적기·조회 화면은 현재 라우트에 맞춰 가져온다. 기존 브랜치의 단계별 독립 고유 수 나눗셈은 순서가 보장되는 퍼널 쿼리로 교체한다.
2. **이벤트 사전과 호환 배포.** SQL 제약과 선택적 컬럼부터 추가한다. 구형 search·download·source_click·request는 검증된 의미만 조회 시 매핑한다. 기존 기록과 신규 버전이 겹치는 구간은 생산자별 전환 시각을 정해 이중 집계를 피한다. 세션·가입 출처가 없는 과거 행은 해당 퍼널에서 미수집으로 표시한다.
3. **계측과 인증 연결.** 페이지·CTA·도메인 이벤트와 소셜 진입 경로를 연결한다. 카카오·구글의 신규·기존·취소·직접 진입·다중 탭을 검증한다. 익명 → 가입 후 같은 기기에서 방문자는 1, 신규 회원은 1, 재콜백 후에도 가입은 1이어야 한다.
4. **대시보드와 상세 인사이트.** 집계가 검증된 지표부터 /admin에 노출한다. KST 자정, 월말, 전주 동시간, 분모 0, 같은 회원의 여러 기기, 가입 D7 미도래, 수집 중단 구간을 테스트한다. 직접 카드에 진입한 세션은 검색 퍼널 분자가 될 수 없다.
5. **회원 운영 출시.** 조회 → 정지·해제 → 권한 변경 순으로 연다. 일반 사용자·읽기 권한 운영자·권한 관리자의 접근 차이, 이전 JWT, 중복 제출, 마지막 관리자 동시 변경을 확인한다.
6. **운영 검증.** 내부 테스트 방문 하나를 페이지 → 기능 클릭 → 소셜 가입 → 첫 활동까지 수행해 저장 행과 집계 결과를 대조한다. 내부 트래픽 제외 후 공개 지표에 잔존하지 않아야 한다. 각 패널은 수집 시작일·공백·마지막 집계 시각을 노출한다. 대시보드 장애 시 작품 관리는 /admin/artworks로 직접 진입한다. 수집기와 대시보드의 독립 중단 설정은 후속 작업이다.

### 운영 권한 초기화

마이그레이션 시 기존 관리자가 한 명이면 그 계정이 회원 관리 권한을 갖는다. 복수이면 운영 DB에서 지정한 기존 관리자에게 `UPDATE admins SET manage_members = true WHERE user_id = $1 RETURNING user_id`를 실행한다. UUID 한 건을 반환하는지 확인한다. 이후 일반 관리자 부여로는 회원 관리 권한이 추가되지 않는다.

### 첫 구현의 조회 기준

- 서버와 브라우저가 쓰는 화면·버튼 목록 및 한글 표기는 [이벤트 사전](../../lib/analytics/taxonomy.ts), 집계식은 [대시보드 쿼리](../../lib/analytics/report.ts)에 있다. 저장 속성명은 `page`, `action`, `placement`다. 기존 검색·다운로드 발급·원본 열기 생산자는 각각 `search`, `download`, `source_click`을 유지한다.
- 기본 조회 기간은 최근 7일이고 상단 방문 카드는 항상 오늘 기준이다. 회원 상세의 소셜 가입 순서는 탈퇴자를 포함한 소셜 계정을 가입 시각과 UUID 순으로 정렬한 값이다.
- 첫 버전은 원시 이벤트를 직접 집계한다. 가입 출처는 서버가 확인한 성공 콜백과 인증 시작을 연결할 수 있을 때 표시한다. 공급자별 표에는 시작과 성공을 표시하며 취소와 이탈 사유의 구분은 후속 작업이다.
- 새 페이지뷰와 가입 출처는 배포 후 관측분부터 누적된다. 원시 이벤트 보관 기한 자동 적용과 월별 장기 집계 보관은 별도 운영 작업으로 남아 있다.


### 패널 상세

운영 대시보드의 카드나 차트 패널을 누르면 `/admin/insights/[topic]`으로 이동한다. 선택 기간과 집계 단위는 URL에 보존한다. 오늘 방문자와 오늘 방문 비교는 오늘을 기준으로 연다. 방문 트래픽은 페이지, 유입은 채널, 가입 전환은 출발 페이지와 버튼, 성장·리텐션은 로그인 방식, 게임은 게임 종류, 요청은 규격으로 좁힐 수 있다. 방문과 성장 차트는 일별·월별 집계를 지원한다.
