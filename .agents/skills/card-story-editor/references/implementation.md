# art-poke 레포에서 발행 가능한 상태로 만들기

- 기존 완성 예시는 `app/stories/stories.ts`의 `pikachu-with-grey-felt-hat`, 조사 예시는 `docs/research/pikachu-with-grey-felt-hat.json`을 본다. 기존 글의 ID는 좋아요·댓글·조회 데이터와 연결되므로 제목이나 편집 내용이 바뀌어도 건드리지 않는다. 새 글에는 새 UUID와 영문 slug를 준다.
- 카테고리는 `domains/story/types.ts`의 `promo`(프로모 뒷이야기), `auction`(낙찰 기록), `release`(새 카드 소식) 중 선택한다. 목록용 한두 문장에는 제목·본문과 다른 재미를 담는다. 글 추가를 위해 기존 필터나 조회수 집계 로직을 복제하지 않는다.
- `app/stories/[slug]/page.tsx`와 기존 목록 카드를 재사용한다. 상세 화면에 고흐츄 전용 거래·사진 블록이 있다면 새 글의 실제 내용에 맞게 선택적으로 표시할 수 있도록 좁게 정리한다. 시세가 없는 신제품 글에 빈 차트나 고흐츄의 라벨·구매자 수수료를 넣지 않는다. 기존 글의 출처 접기, 세로 차트, 사진과 소셜 영역은 확인한다.
- 목록은 독립 사이드 메뉴 **카드 이야기**에서 연다. 흰색·블루 톤의 블로그 헤더와 오른쪽의 기울어진 포켓몬 카드 뒷면, 카테고리 탭을 유지한다. 목록 카드는 커버·소개·조회·좋아요·댓글 수를 보여주고, 선택한 범위에서 조회수 1위는 상단에 한 번만, 나머지는 최신순 무한스크롤로 보여준다.
- 이미지 파일은 `public/specs/stories/`에 실제로 두고 크기·대체 텍스트와 함께 연결한다. 파일을 최적화했다면 조사 JSON에 기록하고, 라이선스에 필요한 출처 정보는 독자도 열어볼 수 있게 둔다.
- 공유용 `shareImage`에는 본문 주제와 제목이 잘 보이는 1200×630 JPG를 연결한다. 상세 페이지의 Open Graph와 X 미리보기 태그가 같은 이미지 주소를 가리키는지 확인한다. 운영 CDN 정적 서빙 경로는 `/specs/stories/`다.
- 타입 검사와 변경 범위 린트를 실행한다. 로컬 브라우저에서 `/stories`, 해당 카테고리 필터, 상세 링크, 이미지 로딩과 모바일 가로 넘침을 확인한다. 차트가 있으면 날짜 오름차순·막대 높이·원화 표시를 확인한다. 로컬 주소는 실행 중인 서버를 확인해서 안내한다.
- 레포에서 글과 사진을 추가하는 일까지 진행하되, 커밋·푸시·운영 발행은 해당 요청에 포함된 경우에 진행한다. 작성 시점과 출처를 갱신하고 검증하지 못한 부분이 남으면 이유와 확인 방법을 적는다.
