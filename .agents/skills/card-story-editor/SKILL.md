# 카드 이야기 집필

카드 팬이 쉬는 시간에 읽고 친구에게 보내고 싶어 하는 긴 블로그 글을 만든다. 글쓴이는 **뮤츠조아요**다. 주제가 주어지면 조사부터 진행한다. 일반 카드 검색, 카탈로그 수집이나 목록 UI만 고치는 요청에는 이 스킬을 적용하지 않는다.

1. **Ego Lite로 조사한다.** 새 주제를 받으면 먼저 `ego-browser` 스킬에 따라 브라우저를 열고 공식 발표, 원자료, 실제 거래 페이지를 살핀다. 웹 검색과 원문 직접 조회로 범위를 넓힌다. 요약문과 검색 결과만으로 발행일이나 시세를 확정하지 않는다.
2. **글보다 근거를 먼저 저장한다.** `docs/research/<slug>.json`에 확인일, 출처 URL과 확인한 사실, 거래 조건, 원본 이미지 URL·크레딧·라이선스를 적는다. 사진은 `public/stories/`에 내려받고, 원본 파일 저장이 어려우면 사용할 수 있는 화면을 Ego Lite로 캡처한다. 직접 확인이 막힌 근거는 접근 가능한 자료로 대조하고 무엇을 확인했는지 기록한다.
3. **한 가지 궁금증을 끝까지 따라간다.** 조사 기록을 바탕으로 도입의 장면, 그 장면을 이해하는 데 필요한 배경, 예상이 달라지는 발견, 처음 질문에 돌아오는 결말을 짧게 잡는다. 카드·사진·거래 기록은 각각 어느 대목에서 독자의 궁금증을 풀어주는지 보고 배치한다. [Melee 글의 구성 예시](references/editorial.md#기승전결을-잡는-법)를 참고한다.
4. **독자에게 얘기하듯 쓴다.** “안녕하세요 뮤츠조아요입니다. 오늘은 … 낋여와봤습니다.”처럼 시작해 궁금한 장면을 먼저 던진다. 장소·인물·카드가 처음 나오면 독자가 따라올 정도로 소개하고, 실제 디테일과 짧은 문단으로 이야기를 길게 풀어낸다. 개인적인 감상과 사실을 구별하고 방문하거나 구매했다는 경험을 꾸며내지 않는다. [말투와 편집 기준](references/editorial.md)을 참고한다.
5. **사진과 숫자를 읽는 위치에 놓는다.** 장소의 첫 언급 뒤에는 실제 풍경, 인물 아래에는 짧은 `*` 별첨, 행사 설명 옆에는 실제 물품이나 현장 사진처럼 그 문단이 궁금하게 만드는 이미지를 붙인다. 거래 수치가 중심이면 날짜 또는 등급을 가로축으로 둔 세로 차트에 원화 금액을 보여주고 원통화와 환율은 조사 기록에 남긴다. 세부 기준은 [말투와 편집 기준](references/editorial.md)에 있다.
6. **아티클과 목록에서 확인한다.** 구현까지 요청했다면 `app/stories/stories.ts`에 고유 ID, slug, 작성자, 날짜, 카테고리, 목록용 소개, 본문을 추가한다. [레포에서 글을 추가하는 법](references/implementation.md)을 따라 목록 필터와 상세 화면에서 검증하고 로컬 미리보기 및 조사 기록을 안내한다. 초안만 요청하면 요청된 형식으로 쓴다.
