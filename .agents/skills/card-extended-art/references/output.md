# 인쇄와 좌표

프로젝트의 [형식 정의](../../../../lib/formats.ts)와 [실물 참고 도면](../../../../components/spec-info.tsx)을 기준으로 한다. mm 좌표의 원점은 왼쪽 위다. 픽셀은 mm × 300 ÷ 25.4를 마지막에 반올림한다.

| 규격 | 전체 mm | 카드 위치와 출력 |
| --- | --- | --- |
| 슬리브 9포켓 | 198 × 276 | 66 × 92 mm씩 3×3. 원본 63 × 88 mm를 중앙에 둔다. |
| 탑로더 9포켓 | 246 × 315 | 82 × 105 mm씩 3×3. 같은 배율의 원본을 중앙에 둔다. |
| PSA | 80 × 135 | 앞면 삽입지 1장. [PSA 도면](../../../../public/specs/psa-slab.png)의 라벨 68 × 20, 카드 63 × 88, 두 영역 사이 약 12 mm. |
| BRG | 80 × 135 | 앞면 삽입지 1장. [BRG 도면](../../../../public/specs/brg-slab.png)의 라벨 66 × 23, 슬랩 상단에서 6, 라벨과 카드 사이 약 7.5 mm. |

9포켓은 246 × 315 mm 전체를 감싸는 마스터에서 같은 중심으로 두 규격을 잘라 쓴다. 실제 카드 비율을 보존한다. 중앙 포켓과 카드 사이의 여백에도 그림이 이어져야 한다. 가로·세로 각 1/3, 2/3 위치에 얇은 재단선을 합성한다. 구간마다 픽셀을 따로 반올림해 누적하지 않는다.

슬랩은 템플릿이나 실측을 제공받으면 그 위치를 우선한다. 기본 시안은 케이스 안에 슬랩을 수평·수직 중앙 정렬한다고 가정한다. BRG 높이 130 mm면 상단 여유 2.5 mm, 라벨 시작 y≈8.5, 카드 y≈39. PSA 도면은 상단 여백 실측 표기가 없어 외곽과 라벨의 화면상 비율로 라벨 y≈5, 카드 y≈37 mm를 추정한다. 두 규격 모두 카드 x≈8.5 mm다. 창의 실제 위치·공차가 확인되지 않은 경우 미리보기와 결과에 도면 기준 추정임을 표시한다. 앞면 삽입지는 카드·등급 라벨이 보일 창을 비운 인쇄용 PNG로 출력하고, 장착 미리보기에서만 카드 원본을 같은 좌표에 겹친다. 창에 실제 라벨 정보가 없으면 비워 둔다.

원본 프레임 안 정규좌표 (u,v)가 [0,1]일 때 출력 좌표는 (카드 왼쪽 + u × 카드 폭, 카드 위 + v × 카드 높이)다. 그림 창 좌표는 먼저 카드 프레임 좌표로 바꾼다. 실제 테두리·문구에 덮인 폭을 가로지를 때는 안쪽 선의 접선을 바깥까지 연장한다. 보호재 크기와 카드 크기를 혼용하면 중심이 맞아도 날개나 도로의 위치가 어긋난다.

## 가이드와 합성 실행

작업 폴더 안에서 새 하위 폴더 이름을 사용한다. 저장소의 `sharp`를 사용하는 [layout.mjs](../scripts/layout.mjs)가 가이드와 출력에 동일한 좌표를 적용한다. 아래 예시의 `9pocket`은 두 PNG를 만들며 `sleeve`, `toploader`, `psa`, `brg`도 선택할 수 있다.

```sh
node .agents/skills/card-extended-art/scripts/layout.mjs guide 9pocket card.png job/geometry job/analysis.json
node .agents/skills/card-extended-art/scripts/layout.mjs render 9pocket card.png job/result registered-art.png "두빅굴"
```

첫 명령은 guide.png와 layout.json을 만든다. layout.json의 master는 가이드 규격, profiles는 각 규격의 canvas·card·label(슬랩)·edges다. edges의 segment_px는 그림 창 경계에서 측정한 구간의 두 끝점으로, 신체 말단이나 카드 은테에서의 도착점을 의미하지 않는다. 은테 밖 예상 위치는 분석한 진행 방향과 가려진 폭으로 정한다. 기존처럼 분석 인수를 생략하면 카드 배치만 담은 가이드를 얻는다. 생성된 그림에서 원본의 눈·어깨·건물 모서리 등 떨어진 지점 세 곳 이상을 같은 가이드와 대조한다. 크기나 중심이 다르면 균일 배율과 이동으로 맞추고, 잘려서 모자라는 바깥은 추가 생성한다. 서로 다른 지점이 한 변환으로 맞지 않으면 잘못 그려진 영역을 다시 그린다. 정렬한 마스터가 두 번째 명령의 registered-art.png다. 각 출력물을 검수한 뒤 해당 회차의 preview.html을 브라우저에서 열고 PNG 전환과 다운로드 대상을 확인한다.

마지막 인수는 표시할 포켓몬 이름이다. 미리보기의 다운로드 버튼으로 실제 파일을 받아 `포켓몬이름_종류.png`인지 확인하고, 검수 기록의 `output`에도 같은 파일명을 기록한다.

## 로컬 웹 미리보기

결과 폴더만 로컬 HTTP로 열어 브라우저의 다운로드 동작을 확인한다. 포트가 사용 중이면 빈 포트로 바꾼다.

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory job/result
```

브라우저에서 `http://127.0.0.1:8765/preview.html`을 열고 각 규격의 버튼을 눌러 실제 저장 파일명을 확인한다.
